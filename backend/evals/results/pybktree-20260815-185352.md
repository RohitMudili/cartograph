> What does hamming_distance do?

The `hamming_distance` function calculates the Hamming distance (the number of differing bits) between two given integers.

- **Parameters**:

- **Return value**: An integer representing the number of bits that differ between `x` and `y`.

### Implementation Details
It computes the bitwise XOR of the two integers, converts the result to a binary string representation using `bin()`, and counts the number of `'1'` characters using `.count('1')`:

### add-and-find

> How does BKTree add items and search for nearby matches?

The `BKTree` class manages adding items and searching for nearby matches using the following mechanisms:

### 1. Adding Items
To add an item, the tree is traversed starting from the root node. If the tree is empty (`self.tree` is `None`), a new root node is created as a two-tuple containing the item and an empty dictionary: `(item, {})`. Otherwise, the tree is navigated iteratively:
- It calculates the distance between the new item and the current parent item using `self.distance_func`.
- It checks if there is already a child node at that distance.
- If no child exists at that distance, a new node `(item, {})` is added to the parent's `children` dictionary.
- If a child node already exists, the traversal continues down into that child node.

### 2. Finding Nearby Matches
The `find(self, item, n)` method searches for all items within a maximum distance of `n` from the target `item`:
- It uses a queue (`collections.deque`) to perform a level-order traversal (breadth-first search) starting from the root node.
- For each candidate node, it calculates the distance between the candidate's item and the target `item`.
- If the calculated distance is less than or equal to `n`, the match is appended to the `found` list as a `(distance, candidate)` tuple.
- To optimize the search and avoid scanning all branches, the tree only traverses child nodes whose distance key `d` satisfies the triangle inequality condition: `distance - n <= d <= distance + n`.
- Finally, the results are sorted by distance in ascending order and returned.

The tree's hierarchical structure is built from nested, native Python data structures rather than custom node objects:
* Each tree node (including the root tracked via `self.tree`) is represented as a **two-tuple**: `(item, children_dict)`.
* `children_dict` is a standard dictionary where the keys are non-negative integer distances and the values are child nodes of the same tuple structure.
* When the tree is empty, `self.tree` is set to `None`.

### Operations & Data Flow

#### 1. Insertion (`add`)
When a new item is added to the tree:
* If the tree is empty (`self.tree is None`), a new node `(item, {})` is created at the root.
* If the tree already contains nodes, the algorithm traverses down the tree iteratively. At each step, it calculates the distance between the new item and the current parent node using the configured `distance_func`. It then checks if a child exists in `children_dict` for that distance:
  * If a child exists, the algorithm moves down to that node and repeats the process.
  * If no child exists, a new node `(item, {})` is inserted under the calculated distance key.

#### 2. Querying (`find`)
To query close matches within a distance of `n` from a given target `item`:
* The method uses a queue (`collections.deque`) initialized with the root node.
* For each candidate node, the distance to the target is computed. If the distance is less than or equal to `n`, the match is added to a results list.
* The search space is pruned by only pushing children to the queue whose keys fall within the range `[distance - n, distance + n]`.

### add-vs-find

> What is the difference between add and find in this codebase?

In the `pybktree` codebase, `add` and `find` are the two core operations of the `BKTree` class, serving distinct purposes, exhibiting different traversal behaviors, and being used in different scenarios.

### 1. The `add` Method
* **Purpose**: The `add` method is used to insert a new item into the BK-tree data structure.
* **Behavior**: If the tree is empty (`self.tree is None`), it sets the root node to `(item, {})`. Otherwise, it traverses down a single path of the tree by calculating the distance between the new item and the current parent node using the configured `distance_func`. It moves to the child node corresponding to that distance. If no child node exists at that distance, it creates a new leaf node `(item, {})` under that distance key and terminates the loop.
* **When Used**: It is used during tree initialization (where it is called iteratively for each element in the `items` list passed to `__init__`) or whenever a user wants to dynamically populate the tree with a new element.

### 2. The `find` Method
* **Purpose**: The `find` method is used to query the tree for items that are "close" (i.e., within a maximum distance metric threshold `n`) to a query item.
* **Behavior**: It performs a breadth-first search (BFS) starting from the root using a `collections.deque` of candidate nodes. For each candidate node, it calculates the distance between the node's item and the query item. If the distance is less than or equal to `n`, it records the match. It then selectively traverses the node's children by extending the queue only with children whose distance keys `d` satisfy the triangle inequality criterion: `distance - n <= d <= distance + n`. Finally, the matched results are sorted by distance and returned as a list of `(distance, item)` tuples.
* **When Used**: It is used when searching for near-matches, such as spelling corrections (Levenshtein distance) or visually similar images (Hamming distance on perceptual hashes).

### Key Differences
* **Mutating vs. Read-Only**: `add` modifies the tree in-place by appending a new node, returning nothing (`None`), while `find` is a read-only query that returns a sorted list of matched items.
* **Traversal Scope**: `add` traverses down a single branch of the tree until it finds an empty slot to insert the node. `find` evaluates multiple paths simultaneously, utilizing a queue to prune branches that fall outside the query range `[distance - n, distance + n]` to optimize search speed.
* **Arguments**: `add` takes only a single argument (`item`), whereas `find` requires two arguments: the search target (`item`) and the maximum distance threshold (`n`).
